Part 1

When tables are not enough

Real tasks have far more states than any table can hold.

Q-learning in one slide

Topic 21 kept one number Q(s, a) per state and action. After each step (s, a, r, s') it computes the TD error:

\delta = r + \gamma \max_{a'} Q(s', a') - Q(s, a)
(1)

and moves that one entry a fraction \alpha toward the target:

Q(s, a) \leftarrow Q(s, a) + \alpha \, \delta
(2)

Actions are chosen \varepsilon-greedily. This topic keeps the same target and changes what stores the values.

Example: equation (1)

Q(s, a) = 0.5, r = 0, \gamma = 0.9, \max_{a'} Q(s', a') = 0.8

\delta = 0 + 0.9 \cdot 0.8 - 0.5 = 0.22

Example: equation (2)

With \alpha = 0.1:

Q(s, a) \leftarrow 0.5 + 0.1 \cdot 0.22

= 0.522

Too many states

A game screen of 84 × 84 pixels with 4 gray levels can show 4^{7056} \approx 10^{4248} different images. A table would need one row for each.

Even a long training run visits a tiny fraction of them. A table learns nothing about a state it has never seen.

Figure 1:(a) A small screen. (b) Number of states; bar length is the number of digits. (c) States visited in training.

From a table to a function

A table has no answer for a new state. A function Q(s, a; \boldsymbol\theta) takes the state as numbers and returns one value per action.

All states share the same parameters \boldsymbol\theta. Learning from one state also changes the values of similar states: the function generalizes.

Figure 2:(a) A table only knows the states it has seen. (b) A network with the state as input and one output per action.

A linear Q-function

Describe the state by features \boldsymbol\phi(s), and give each action its own weight vector \boldsymbol\theta_a:

Q(s, a; \boldsymbol\theta) = \boldsymbol\theta_a^\top \boldsymbol\phi(s) = \sum_k \theta_{a,k} \, \phi_k(s)
(3)

Learning moves each weight in proportion to its feature:

\boldsymbol\theta_a \leftarrow \boldsymbol\theta_a + \alpha \, \delta \, \boldsymbol\phi(s)
(4)
Example: equation (3)

\boldsymbol\phi(s) = (1, 0.5)

\boldsymbol\theta_{\rightarrow} = (0.2, 0.6)

Q(s, \rightarrow) = 0.2 \cdot 1 + 0.6 \cdot 0.5

= 0.5

Example: equation (4)

\delta = 0.2, \alpha = 0.1

\boldsymbol\theta_{\rightarrow} \leftarrow (0.2, 0.6) + 0.02 \, (1, 0.5)

= (0.22, 0.61)

A table is the special case where each feature marks one state.

Part 2

Deep Q-networks

A neural network learns Q-values with the Q-learning target, plus two tricks that keep training stable.

The DQN loss

For each transition (s_i, a_i, r_i, s'_i) in a mini-batch, the target uses a frozen copy \boldsymbol\theta^{-}; it is just r_i if s'_i is terminal:

y_i = r_i + \gamma \max_{a'} Q(s'_i, a'; \boldsymbol\theta^{-})
(5)

The loss is the mean squared TD error over the B transitions:

L(\boldsymbol\theta) = \frac{1}{B} \sum_{i=1}^{B} \big( y_i - Q(s_i, a_i; \boldsymbol\theta) \big)^2
(6)

Backpropagation (Topic 23) gives the gradient; \boldsymbol\theta takes a small step against it, with y_i held fixed:

\boldsymbol\theta \leftarrow \boldsymbol\theta - \alpha \, \nabla_{\boldsymbol\theta} L(\boldsymbol\theta)
(7)
Example

B = 2, \gamma = 0.9

1: r = 1, \max Q(s', \cdot\,; \boldsymbol\theta^{-}) = 2.0

Q(s, a; \boldsymbol\theta) = 2.5

y_1 = 1 + 0.9 \cdot 2.0 = 2.8

2: terminal, r = -1, Q(s, a; \boldsymbol\theta) = -0.6

y_2 = -1

errors 0.3 and −0.4:

L = \tfrac{1}{2} (0.09 + 0.16) = 0.125

The step raises Q in case 1 and lowers it in case 2.

Why naive training fails

Training on each step as it comes breaks two habits of gradient descent.

Correlated data: consecutive frames are almost the same, so each update pushes the network toward one situation and it forgets others.

A moving target: y is computed with the same \boldsymbol\theta we update, so every step also moves the target.

Figure 3:(a) Five consecutive frames. (b) The estimate Q chases a target y that keeps moving away.

Experience replay

Each step is stored in a buffer \mathcal{B}. When full, the oldest is replaced. Training samples a random mini-batch, so one batch mixes old and new situations.

A frozen target network

Keep a second copy \boldsymbol\theta^{-} to compute targets. It stays fixed while \boldsymbol\theta learns, and every C steps we copy \boldsymbol\theta^{-} \leftarrow \boldsymbol\theta.

Between copies, training is ordinary regression toward fixed targets.

The DQN algorithm

Every step has two halves. The agent acts with the current network and stores what happened.

Then it learns from a random mini-batch of old steps, using equations (5) to (7) and the frozen copy for targets.

Figure 6:Deep Q-learning with experience replay and a target network.

Playing Atari from pixels

In 2015 one DQN design learned 49 Atari games. The input was only the screen and the score; the network, its settings and the training were the same for every game.

Convolution layers (Topic 25) read the last 4 frames. It reached at least 75% of a human tester's score in 29 of the 49 games.

Part 3

Learning policies directly

Skip the values: let a network output the probabilities of the actions.

A policy network

The network outputs one preference h_a(s; \boldsymbol\theta) per action. A softmax turns preferences into probabilities:

\pi_{\boldsymbol\theta}(a \mid s) = \frac{e^{h_a(s; \boldsymbol\theta)}}{\sum_b e^{h_b(s; \boldsymbol\theta)}}
(8)

The agent samples its action from these probabilities, so it explores on its own.

Example

h = (2, 1, 0)

e^2 + e^1 + e^0 \approx 11.11

\pi \approx (0.67, \ 0.24, \ 0.09)

Why a policy?

It works with many or continuous actions, where taking a max over Q is hard.

The policy gradient

Let J(\boldsymbol\theta) be the expected return. Its gradient is

\nabla_{\boldsymbol\theta} J = \mathbb{E}\big[ G_t \, \nabla_{\boldsymbol\theta} \log \pi_{\boldsymbol\theta}(A_t \mid S_t) \big]
(9)

In words: make actions that led to a high return more likely. REINFORCE plays an episode and takes a step uphill:

\boldsymbol\theta \leftarrow \boldsymbol\theta + \alpha \, G_t \, \nabla_{\boldsymbol\theta} \log \pi_{\boldsymbol\theta}(A_t \mid S_t)
(10)

If the parameters are the preferences themselves, the chosen action a goes up and the others go down:

h_b \leftarrow \begin{cases} h_b + \alpha \, G \, \big(1 - \pi(b)\big) & b = a \\ h_b - \alpha \, G \, \pi(b) & b \neq a \end{cases}
(11)
Example

Three actions, h = (0, 0, 0), so \pi = (\tfrac13, \tfrac13, \tfrac13).

Action 1 is chosen, G = 1, \alpha = 0.5.

h_1 = 0.5 \cdot \tfrac23 \approx 0.33

h_2 = h_3 = -0.5 \cdot \tfrac13 \approx -0.17

\pi \approx (0.45, \ 0.27, \ 0.27)

REINFORCE on three arms

Each pull samples an arm from \pi; the reward G is 1 or 0. Equation (11) updates h.

Actor-critic

The return G_t is noisy. A second network, the critic, learns V(s). The actor \pi_{\boldsymbol\theta} then uses the advantage: how much better the action was than usual.

A(s, a) = Q(s, a) - V(s)
(12)

One step gives an estimate, the TD error, used in place of G_t in (10):

\delta = r + \gamma V(s') - V(s)
(13)
Example

V(s) = 2, r = 1, \gamma = 0.9, V(s') = 1.5

\delta = 1 + 0.9 \cdot 1.5 - 2 = 0.35

Positive: the action was better than expected, so the actor makes it more likely. The critic moves V(s) toward 2.35.

Milestones

Games came first: they have clear rewards and cheap simulators, so an agent can play millions of times.

Later the same ideas moved to robots trained in simulation and to chat models, where people rank answers and the ranking becomes the reward.

Strengths and weaknesses

Table 2:Deep reinforcement learning at a glance.

StrengthsWeaknesses
Handles huge or continuous state spacesNeeds millions of interactions
Learns from raw input such as pixelsTraining is unstable and sensitive to settings
Generalizes to states it has never visitedLoses the convergence guarantee of tables
Policy methods handle many or continuous actionsAgents exploit flaws in the reward
One method can learn many different tasksHard to explain, and risky in the real world
When to use it

Sequential decisions with a clear reward, a fast simulator to practice in, and too many states for a table.

Key ideas

Remember
  • When states are too many, a network Q(s, a; \boldsymbol\theta) replaces the table and generalizes to similar states.
  • DQN minimizes the squared TD error on random mini-batches.
  • Experience replay breaks correlations; a frozen target network \boldsymbol\theta^{-} keeps targets still.
  • Policy gradients learn \pi_{\boldsymbol\theta}(a \mid s) directly; actor-critic adds a critic to reduce noise.
  • Deep RL masters games but needs many samples and a carefully designed reward.
