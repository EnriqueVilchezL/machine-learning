Part 1

From words to vectors

Text becomes a list of vectors, and each word asks which others matter.

Where recurrent networks struggle

A recurrent network (Topic 26) reads one token per step and keeps a memory \mathbf{h}_t.

Two problems: steps cannot run in parallel, and the memory of an early word fades over many steps.

Attention links every pair of tokens directly, in one step.

Figure 1:(a) “animal” reaches “it” only through five memory updates. (b) With attention, “it” looks at every word at once.

Tokens and embeddings

Text is split into tokens: whole words or common pieces of words. Each token has a number in a fixed vocabulary.

Each token number is replaced by a learned vector, its embedding \mathbf{x}_t.

Training places words used in similar ways close together.

Figure 2:(a) A sentence cut into tokens, each mapped to a vector. (b) Made-up 2-D embeddings; real ones have hundreds of numbers.

Which words matter?

To understand “it”, a reader must find what “it” refers to: the animal, not the street.

Attention gives each word a set of weights over all words. A large weight means “this word matters for me”.

The new vector for “it” mixes in mostly the vector of “animal”.

Figure 3:Line width shows the weight from “it” to each word. Weights from the small made-up vectors of Figure 5.

Part 2

Attention

Compare, turn scores into weights, and take a weighted average.

Queries, keys and values

Each token makes three vectors from its embedding, with three learned matrices.

A token compares its query with the key of every token. A good match means a large weight.

It then collects the values of the tokens, using those weights.

Figure 4:The token “it” and its three vectors. Made-up numbers with 4 entries each.

From scores to weights

The query of token t meets the key of token j. Their dot product is large when the two vectors point the same way:

s_{tj} = \mathbf{q}_t^\top \mathbf{k}_j = \sum_{m=1}^{d_k} q_{tm}\, k_{jm}
(1)

Softmax turns the T scores into positive weights that add up to 1:

a_{tj} = \frac{e^{s_{tj}}}{\sum_{j'=1}^{T} e^{s_{tj'}}}
(2)

The output for token t is the weighted average of the values:

\mathbf{o}_t = \sum_{j=1}^{T} a_{tj}\, \mathbf{v}_j
(3)
Example

Tokens “the cat it”. Query of “it”: (1, 0).

Keys (0, 1), (2, 1), (1, 0) give scores 0, 2, 1.

e^0 + e^2 + e^1 \approx 11.11

Weights: 0.090, \ 0.665, \ 0.245

Output

Values (0, 1), (1, 0), (0, 1).

First entry: 0.665. Second: 0.090 + 0.245 = 0.335.

\mathbf{o} = (0.665, \ 0.335)

Scaled dot-product attention

The queries, keys and values of all tokens come from the embeddings through three learned matrices:

\mathbf{Q} = \mathbf{X}\mathbf{W}_Q, \qquad \mathbf{K} = \mathbf{X}\mathbf{W}_K, \qquad \mathbf{V} = \mathbf{X}\mathbf{W}_V
(4)

Equations (1) to (3) for all tokens at once, with softmax applied to each row:

\text{Attention}(\mathbf{Q}, \mathbf{K}, \mathbf{V}) = \underbrace{\text{softmax}\!\left(\frac{\mathbf{Q}\mathbf{K}^\top}{\sqrt{d_k}}\right)}_{\mathbf{A}} \mathbf{V}
(5)

Why \sqrt{d_k}: a dot product adds d_k terms, so scores grow with the key size. Large scores push softmax to all-or-nothing weights, and learning slows down.

Example

With d_k = 64, scores (0, 16, 8) give weights

(0.000, \ 0.9997, \ 0.0003).

Divided by \sqrt{64} = 8: scores (0, 2, 1), weights

(0.090, \ 0.665, \ 0.245).

Shapes

\mathbf{Q}\mathbf{K}^\top is T \times T: one row of weights for each token.

Self and cross attention

Self-attention: queries, keys and values all come from the same sentence.

Encoder–decoder attention: queries come from the sentence being written, keys and values from the input sentence.

This second kind first appeared in translation with recurrent networks (Bahdanau et al., 2015).

Figure 6:(a) A sentence attends to itself. (b) Spanish words being written attend to the English input. Illustrative weights.

Multi-head attention

\text{head}_i = \text{Attention}\big(\mathbf{X}\mathbf{W}_Q^{(i)}, \ \mathbf{X}\mathbf{W}_K^{(i)}, \ \mathbf{X}\mathbf{W}_V^{(i)}\big), \quad i = 1, \dots, h
(6)
\text{MultiHead}(\mathbf{X}) = \big[\text{head}_1, \dots, \text{head}_h\big]\, \mathbf{W}_O
(7)

One set of weights captures one kind of relation. A model runs h heads side by side, each with its own matrices.

The outputs are placed side by side and mixed by \mathbf{W}_O.

Example

d_{\text{model}} = 512 and h = 8.

Each head: d_k = 512 / 8 = 64

Side by side: 8 \cdot 64 = 512

Figure 7:Three of h heads on “the cat sat on mat”. Darker cell: larger weight. Illustrative patterns.

Adding word order

Attention compares pairs and ignores where tokens sit: “dog bites man” and “man bites dog” give the same weights. So a position vector is added to each embedding:

\mathbf{x}_t \;\leftarrow\; \mathbf{x}_t + \mathbf{p}_t
(8)

The original transformer uses waves of different speeds, with i = 0, 1, \dots, d_{\text{model}}/2 - 1:

p_{t,2i} = \sin\!\left(\frac{t}{10000^{2i/d_{\text{model}}}}\right), \qquad p_{t,2i+1} = \cos\!\left(\frac{t}{10000^{2i/d_{\text{model}}}}\right)
(9)

Early entries change fast and later ones slowly, like the hands of a clock. Each position gets its own pattern.

Example

d_{\text{model}} = 4, position t = 1. For i = 1: 10000^{2/4} = 100.

p_{1,0} = \sin 1 \approx 0.841
p_{1,1} = \cos 1 \approx 0.540
p_{1,2} = \sin 0.01 \approx 0.010
p_{1,3} = \cos 0.01 \approx 1.000

Learned positions

Many later models learn \mathbf{p}_t as parameters instead.

Part 3

The transformer and language models

Stack attention into blocks, then learn to predict the next token.

The transformer block

\mathbf{Z} = \text{Norm}\big(\mathbf{X} + \text{MultiHead}(\mathbf{X})\big)
(10)
\mathbf{Y} = \text{Norm}\big(\mathbf{Z} + \text{FFN}(\mathbf{Z})\big), \quad \text{FFN}(\mathbf{z}) = \text{ReLU}(\mathbf{z}\mathbf{W}_1 + \mathbf{b}_1)\,\mathbf{W}_2 + \mathbf{b}_2
(11)

Residual connection: the input skips around each part and is added back.

Normalize: rescale each token's vector to mean 0, spread 1.

Example

(1, 2) + (0.5, -1) = (1.5, 1)

Mean 1.25, spread 0.25: (1, -1)

Figure 9:One block; models stack N of them.

Encoder, decoder and mask

\mathbf{A} = \text{softmax}\!\left(\frac{\mathbf{Q}\mathbf{K}^\top}{\sqrt{d_k}} + \mathbf{M}\right), \qquad M_{tj} = \begin{cases} 0 & j \le t \\ -\infty & j > t \end{cases}
(12)

An encoder reads the whole input, so every token sees every token. A decoder writes text and must not look ahead.

Predicting the next token

A decoder reads tokens 1 to t. Its last vector \mathbf{h}_t gets one score per vocabulary token, and softmax turns the |\mathcal{V}| scores into probabilities:

P(x_{t+1} = w \mid x_1, \dots, x_t) = \text{softmax}\big(\mathbf{h}_t \mathbf{W} + \mathbf{b}\big)_w
(13)

Training uses cross-entropy (Topic 23): minus the log of the probability given to the real next token, averaged over all positions.

\begin{gathered} L_t = -\log P(x_{t+1} = \text{real token} \mid x_1, \dots, x_t) \\ J(\boldsymbol{\theta}) = \frac{1}{T-1} \sum_{t=1}^{T-1} L_t \end{gathered}
(14)

Every position of every text is one training example. No one has to write labels: the text itself is the answer key.

Example

“the cat sat on the”, real next token “mat”, natural log:

P = 0.6: \ -\log 0.6 \approx 0.51

P = 0.05: \ -\log 0.05 \approx 3.00

Size

\mathbf{W} has one column per token, so |\mathcal{V}| columns, often tens of thousands.

Generating text

P(w) = \frac{e^{z_w / \tau}}{\sum_{v \in \mathcal{V}} e^{z_v / \tau}}
(15)

Pick a token, add it, predict again. \tau divides each score z_w.

Chance of “mat”0%

Pretraining at scale

Topic 29: pretrain on a large general task, then fine-tune on your own small task.

For language the general task is predicting words in raw text: no labels needed.

Parameters grew about 2 700 times in three years. Larger models did better, at a higher cost.

Limits and responsibility

Cost

T^2 pairs: twice the text, four times the work.

Made-up facts

Likely words are not always true.

Bias

It repeats patterns in its data, unfair ones too.

Energy

Large models use much electricity and hardware.

Sequences with long-range links, above all when a pretrained model exists for your kind of data.

Key ideas

Remember
  • Text becomes tokens, and each token becomes a learned vector.
  • Attention scores each query against every key, turns the scores into weights with softmax and averages the values.
  • Dividing by \sqrt{d_k}, several heads and position vectors make attention work in practice.
  • A block is attention plus a feed-forward layer, each with a residual connection and normalization.
  • Language models learn to predict the next token from raw text, then are fine-tuned for a task.
