Part 1

Reusing what was learned

A network trained on one task already knows a lot about the next one.

Recap: networks and CNNs

Each layer computes g(\mathbf{W}^{(l)}\mathbf{a} + \mathbf{b}^{(l)}) from the layer before (Topic 23).

Training repeats: forward pass, loss, backpropagation, and the update \boldsymbol\theta \leftarrow \boldsymbol\theta - \alpha \nabla J.

A CNN uses convolution and pooling to read images (Topic 25).

Figure 1:(a) A small network. (b) The training loop. (c) A CNN for images.

Too little labeled data

Deep networks learn from very many labeled examples and days of computing.

A local task may have only 300 photos, for example coffee leaves with and without rust.

From scratch, millions of parameters would memorize 300 photos and overfit.

Figure 2:Each small square is 1000 labeled photos. Sizes are typical for a large photo collection and a small local project.

Source and target tasks

Someone who rides a bike learns a motorcycle faster: balance and steering carry over.

Transfer learning trains a network on a large source task, then reuses its parameters \boldsymbol\theta_S on a small target task.

Figure 3:(a) Skills move from one task to a related one. (b) The same idea with a network.

General to specific layers

Early layers detect edges and textures. Almost every image task needs them.

Later layers combine them into parts and objects of the source task, so they are more specific.

The output layer only fits the source classes, so we always replace it.

Figure 4:A CNN from input to output. Color goes from general (blue) to task specific (orange), as measured by Yosinski et al. (2014).

When transfer helps

The closer the target is to the source, the more the reused features help.

With a very different domain, the source features can mislead the target model. This is negative transfer: worse than training from scratch.

Always compare with a model trained from scratch.

Figure 5:Illustrative sketch, not measured data: gain in accuracy over training from scratch as the domains grow apart.

Part 2

Three ways to transfer

Freeze the body, fine-tune it, or pick between them by the data you have.

Feature extraction

Keep the pretrained body frozen: its parameters do not change.

The body turns each photo into a feature vector \boldsymbol\phi(\mathbf{x}).

Only a new head for the target classes is trained, like a logistic regression on those features.

Figure 6:A 50-layer ResNet body (Topic 25) with a new head for 5 classes of coffee leaves.

The new head

The frozen body maps an input to features, using the source parameters \boldsymbol\theta_S without changing them:

\mathbf{x} \;\longmapsto\; \boldsymbol\phi(\mathbf{x}) \in \mathbb{R}^{2048}
(1)

The head turns the features into one probability per class:

\hat{\mathbf{y}} = \text{softmax}\big(\mathbf{W}_{\text{head}}\, \boldsymbol\phi(\mathbf{x}) + \mathbf{b}_{\text{head}}\big)
(2)

With 5 classes, \mathbf{W}_{\text{head}} is 5 \times 2048 and \mathbf{b}_{\text{head}} has 5 entries:

|\boldsymbol\theta_{\text{head}}| = 2048 \cdot 5 + 5 = 10\,245
(3)
Example

Two features \boldsymbol\phi = (1, 2), two classes, \mathbf{W}_{\text{head}} = \mathbf{I}, \mathbf{b}_{\text{head}} = \mathbf{0}.

Scores (1, 2), so

\hat{y}_2 = \tfrac{e^2}{e^1 + e^2} \approx 0.73

Count

Body: 23 508 032 frozen.

Head: 10 245 trainable, about 0.04% of the total.

Fine-tuning

Fine-tuning also trains the body. Gradient descent starts at the source parameters instead of random ones:

\boldsymbol\theta^{(0)} = \boldsymbol\theta_S
(4)

Each step lowers the target cost J_T, the average loss on the n_T target examples:

\boldsymbol\theta \leftarrow \boldsymbol\theta - \alpha_{\text{ft}}\, \nabla J_T(\boldsymbol\theta), \qquad J_T(\boldsymbol\theta) = \frac{1}{n_T} \sum_{i=1}^{n_T} L(y_i, \hat{y}_i)
(5)

A small \alpha_{\text{ft}} keeps the useful source features. Unfreeze gradually: first the head, then the last block, then earlier blocks.

Example

A weight starts at \theta_S = 0.80 with gradient 0.5.

With \alpha_{\text{ft}} = 0.001:

0.80 - 0.001 \cdot 0.5 = 0.7995

With \alpha = 0.1:

0.80 - 0.1 \cdot 0.5 = 0.75

The large step moves the weight 100 times farther from what it learned.

Staying near the source

Another way to keep what was learned: add a penalty for moving away from \boldsymbol\theta_S.

J_T(\boldsymbol\theta) + \lambda \,\lVert \boldsymbol\theta - \boldsymbol\theta_S \rVert^2
(6)

The first term asks for a good fit to the few target examples. The second is the squared distance to the source solution.

\lambda = 0 ignores the source; a large \lambda keeps \boldsymbol\theta at \boldsymbol\theta_S. A model from scratch uses the usual penalty toward zero:

J_T(\boldsymbol\theta) + \lambda \,\lVert \boldsymbol\theta \rVert^2
(7)
Example

One parameter. The target data alone give J_T = (\theta - 4)^2, and \theta_S = 2.

Minimizing

(\theta - 4)^2 + \lambda(\theta - 2)^2

gives \theta = \tfrac{4 + 2\lambda}{1 + \lambda}:

\lambda = 0: \theta = 4

\lambda = 1: \theta = 3

\lambda = 3: \theta = 2.5

Part 3

In practice

Prepare the inputs, guard against overfitting, and use pretrained models with care.

Preparing the inputs

Feed the target photos exactly as the source photos were fed: same size, same normalization (Topic 4):

x' = \dfrac{x - \mu_S}{\sigma_S}

Red value 0.60 with \mu_S = 0.485, \sigma_S = 0.229: x' \approx 0.50.

Augmentation makes new training photos from old ones.

Figure 11:(a) Resize and normalize with the source statistics. (b) Four variants of one leaf photo.

Validation with few examples

With 300 photos the network can memorize the training set within a few passes.

Keep a validation set and stop when its accuracy stops improving.

Choose \alpha_{\text{ft}} and the frozen layers there too. With tiny data, use k-fold cross-validation (Topic 6).

Figure 12:Illustrative training run on a 240/60 split of the 300 photos.

Domain shift

Source photos are often clean and centered. Field photos have shadows, mud and other leaves.

The features then take different values, and a rule learned on the source lands in the wrong place.

Fix: fine-tune with photos taken in the real setting.

Figure 13:(a) Source and target photos. (b) One feature in each domain; the dashed line is the rule learned on the source.

Pretrained language models

Text works the same way. First, a network reads a huge amount of text and learns to predict hidden words. No labels are needed.

Then it is fine-tuned on a small labeled set, such as 2000 reviews marked positive or negative.

Topic 31 shows the networks behind these models.

Figure 14:Pretraining on unlabeled text, then fine-tuning for one task.

Foundation models

A foundation model is one very large network pretrained on very varied data.

Many tasks start from it: by fine-tuning, by training a small head, or by describing the task in words.

Pretraining costs a lot once; each new task then costs little.

Figure 15:One pretrained model at the center, adapted to many target tasks.

Responsible use

A pretrained model carries its source data with it, including its gaps and biases.

Weights and data come with licenses. Read the terms before using them, above all for commercial work.

Test on every group of users and write down where the model came from.

Strengths and weaknesses

StrengthsWeaknesses

Training takes minutes or hours, not daysNegative transfer when domains are far apart
Feature extraction trains very few parametersInputs must match the source size and normalization
Works for images, text and soundInherits the biases of the source data
One pretrained model serves many tasksLarge pretrained models are slow and subject to licenses
When to use it

The default start for images and text when labeled data are scarce and a related pretrained network exists.

Key ideas

Remember
  • Transfer learning reuses parameters \boldsymbol\theta_S learned on a large source task for a small target task.
  • Early layers learn general features; later layers and the output are task specific.
  • Feature extraction freezes the body and trains a new head; fine-tuning also updates the body with a small \alpha_{\text{ft}}.
  • Little data and a similar domain favor freezing more layers; validate every choice.
  • Match the source inputs, watch for domain shift, and check bias and licenses.
