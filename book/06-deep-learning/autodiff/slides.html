Reading the symbols

\partial a / \partial b is a slope: how much a changes for a small change in b.

For training, y is the cost J and \mathbf{x} holds the parameters \boldsymbol\theta.

Running example

f(x_1, x_2) = \ln x_1 + x_1 x_2 - \sin x_2 at (2, 5).

Part 1

Three ways to differentiate

By formula, by nudging the input, or by following the program.

Gradients drive learning

Gradient descent (Topic 23) needs the slope of the cost along every parameter, at every step:

\boldsymbol{\theta} \leftarrow \boldsymbol{\theta} - \alpha \, \nabla_{\boldsymbol{\theta}} J(\boldsymbol{\theta}), \qquad \nabla_{\boldsymbol{\theta}} J = \Big(\frac{\partial J}{\partial \theta_1}, \dots, \frac{\partial J}{\partial \theta_n}\Big)
(1)

Deriving these slopes by hand for each new model is slow and error-prone. Automatic differentiation (AD) lets the computer find them from the code that computes J.

Example

The small network of Topic 23 has 7 894 parameters.

Each step of (1) needs 7 894 slopes, and training takes thousands of steps.

Automatic differentiation

Every program is built from a few elementary operations whose derivatives are known. AD applies the chain rule to the numbers those operations produce while the program runs, never to a formula.

Part 2

Computational graphs

Break the program into small steps and draw who feeds whom.

The evaluation trace

Running f computes one elementary operation at a time. Each result is a new variable:

v_i = \varphi_i(\text{parents of } v_i)
(3)

v_1 = \ln x_1 = 0.693

v_2 = x_1 x_2 = 10

v_3 = \sin x_2 = -0.959

v_4 = v_1 + v_2 = 10.693

y = v_5 = v_4 - v_3 = 11.652

Figure 3:The graph of f(x_1, x_2) = \ln x_1 + x_1 x_2 - \sin x_2 at (2, 5). Values in blue.

Local derivatives

Each operation knows its slope with respect to each input:

u + w: \quad 1, \ 1

u \cdot w: \quad w, \ u

\sin u: \quad \cos u

\ln u: \quad 1/u

\tanh u: \quad 1 - \tanh^2 u

Figure 4:The same graph with the local derivative on every arrow.

The chain rule on the graph

To get \partial y / \partial x_1, follow every path from x_1 to y. Multiply the local derivatives along each path, then add the paths:

\frac{\partial y}{\partial x_1} = \sum_{\text{paths}} \ \prod_{\text{arrows}} \text{local derivative}
(4)

\text{via } v_1\!: \ \tfrac{1}{x_1} \cdot 1 \cdot 1 = 0.5

\text{via } v_2\!: \ x_2 \cdot 1 \cdot 1 = 5

\partial y / \partial x_1 = 0.5 + 5 = 5.5

Check by hand

\partial f / \partial x_1 = 1/x_1 + x_2 = 5.5 ✓

Figure 5:The two paths from x_1 to y.

Too many paths

Listing paths does not scale. In a network with L layers of k units, each input reaches the output through k^{L} paths, and most of them share arrows.

The fix is to compute the same sum one node at a time, reusing what was already computed:

  • Forward mode starts at an input and stores, at every node, its slope with respect to that input.
  • Reverse mode starts at the output and stores, at every node, the slope of the output with respect to it.

Both give exactly the result of (4). They only change the order of the multiplications.

Example

3 layers of 100 units: 100^3 = 10^6 paths from each input.

Node by node, each arrow is used once.

Figure 6:Three layers of 4 units: 4^3 = 64 paths from x to y. Three of them are highlighted.

Part 3

Forward mode

Apply the chain rule node by node, from the inputs to the output.

Forward mode by hand

Fix one input, x_1. Visit the nodes from left to right. Each node multiplies the arrows coming in by the slopes already found at their start, and adds:

\frac{\partial v_i}{\partial x_1} = \sum_{j \,\in\, \text{parents}(i)} \frac{\partial v_i}{\partial v_j} \, \frac{\partial v_j}{\partial x_1}
(5)

Start from \partial x_1 / \partial x_1 = 1 and \partial x_2 / \partial x_1 = 0.

One pass, one input

For \partial y / \partial x_2, run again from \partial x_2 / \partial x_2 = 1.

Part 4

Reverse mode

Apply the chain rule node by node, from the output back to the inputs.

Reverse mode by hand

After a forward pass, visit the nodes from right to left. Each node multiplies its outgoing arrows by the slopes found at their ends, and adds:

\frac{\partial y}{\partial v_j} = \sum_{i \,\in\, \text{children}(j)} \frac{\partial y}{\partial v_i} \, \frac{\partial v_i}{\partial v_j}
(6)

Start from \partial y / \partial y = 1.

One pass, all inputs

One backward pass gives the slopes for both inputs.

Figure 9:Local derivatives on the arrows; slopes of y under the nodes, at (2, 5).

Five steps forward store the values. Then, from \partial y / \partial y = 1, five steps back apply (6).

Branches add up

When a variable feeds several operations, the terms from each one add up, as in (6).

Example

In y = x \cdot x each branch gives x, so \partial y / \partial x = x + x = 2x, the derivative of x^2.

Common bug

Keeping only the last branch gives a wrong slope.

Part 5

Inside an engine

What a reverse-mode engine records, in what order it works, and what it costs.

What an engine stores

Each operation of the forward pass creates a node. The backward pass then:

  1. Sorts the nodes so that every node comes after its parents.
  2. Sets all gradients to 0 and the output’s to 1.
  3. Visits the nodes from last to first. Each one adds its gradient × local derivative to each parent.

Figure 13:(a) One node. (b) The order of the visits.

Cost and memory

Each node does a fixed amount of work on the way back, so for a scalar output:

\text{time}(\nabla f) \le c \cdot \text{time}(f)
(8)

with a small constant c that does not grow with n. The price is memory: every forward value waits for the backward pass.

Checkpointing

Keep some values and recompute the rest on the way back: more time, less memory.

Strengths and weaknesses

Table 4:Automatic differentiation at a glance.

StrengthsWeaknesses
Exact derivatives, up to roundingReverse mode keeps every intermediate value in memory
The full gradient of a cost for a few evaluationsForward mode needs one pass per input
Works on programs with loops and branchesAt kinks such as ReLU at 0 it returns one chosen slope
No derivative is written by hand for a new modelIt differentiates the code as written, including its shortcuts
Which mode

Reverse mode when there are many inputs and one output, as in training. Forward mode when there are few inputs and many outputs.

Key ideas

Remember
  • A program is a chain of simple operations; the chain rule multiplies their local derivatives along each path and adds the paths.
  • Symbolic formulas swell and finite differences are approximate; AD is exact and cheap.
  • Forward mode applies the chain rule from one input onward: one pass per input.
  • Reverse mode stores the values, then applies it from the output backward: one pass gives every input.
  • Backpropagation is reverse mode on a network; branches add up.
