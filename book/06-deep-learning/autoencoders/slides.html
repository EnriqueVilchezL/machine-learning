Reading the symbols

Bold letters are vectors or matrices.

The decoder g_{\boldsymbol\psi} always carries its subscript. A plain g is an activation, as in Topic 23.

A hat marks a reconstruction and a tilde a noisy input. The sign \odot multiplies two vectors entry by entry.

Part 1

Copy through a bottleneck

A network whose target is its own input.

Output your own input

An autoencoder is a network trained to output its own input. No labels are needed.

The middle layer, the code \mathbf{z}, has q numbers, fewer than the d inputs.

The encoder squeezes the input into the code. The decoder rebuilds \hat{\mathbf{x}} from the code alone.

Figure 1:A 5 × 7 picture: 35 numbers in, a code of 2, 35 out. The output is close to the input, not equal.

Why a narrow middle

With a middle as wide as the input, the network can pass each number straight through. It copies perfectly and learns nothing about the data.

With only q numbers in the middle, it must keep what matters most and drop the rest.

To rebuild many examples well, it has to find the patterns they share. The code is a compression learned from data.

Figure 2:(a) A wide middle allows a plain copy (orange). (b) A narrow middle forces 6 numbers into 2.

The reconstruction loss

The encoder maps an example to its code, and the decoder maps the code back:

\mathbf{z}_i = f_{\boldsymbol\phi}(\mathbf{x}_i)
(1)
\hat{\mathbf{x}}_i = g_{\boldsymbol\psi}(\mathbf{z}_i) = g_{\boldsymbol\psi}\big(f_{\boldsymbol\phi}(\mathbf{x}_i)\big)
(2)

Training makes the reconstruction close to the input. The cost is the average squared distance between them, the same reconstruction error as in PCA:

J(\boldsymbol\phi, \boldsymbol\psi) = \frac{1}{n} \sum_{i=1}^{n} \lVert \mathbf{x}_i - \hat{\mathbf{x}}_i \rVert^2
(3)

Encoder and decoder are trained together, by gradient descent on J.

Example

\mathbf{x}_1 = (1, 0, 2)

\hat{\mathbf{x}}_1 = (0.8, 0.1, 1.7)

0.2^2 + 0.1^2 + 0.3^2 = 0.14

\mathbf{x}_2 = (0, 1, 1)

\hat{\mathbf{x}}_2 = (0.2, 0.9, 1.0)

0.2^2 + 0.1^2 + 0^2 = 0.05

J = (0.14 + 0.05)/2 = 0.095

One layer each way

The simplest autoencoder has one layer in the encoder and one in the decoder, built as in Topic 23:

\mathbf{z} = g\big(\mathbf{W}_1 \mathbf{x} + \mathbf{b}_1\big), \qquad \mathbf{W}_1 \text{ is } q \times d
(4)
\hat{\mathbf{x}} = \mathbf{W}_2\, \mathbf{z} + \mathbf{b}_2, \qquad \mathbf{W}_2 \text{ is } d \times q
(5)

All weights and biases form \boldsymbol\theta = (\boldsymbol\phi, \boldsymbol\psi). Backpropagation gives the gradient of J, and each step moves against it:

\boldsymbol\theta \leftarrow \boldsymbol\theta - \alpha\, \nabla_{\boldsymbol\theta} J
(6)

Deeper autoencoders stack more layers on each side, usually shrinking toward the code and growing back.

Example

d = 3, q = 1, g(t) = t, zero biases.

\mathbf{W}_1 = (0.5,\ 0.5,\ 0)

\mathbf{W}_2 = (1, 1, 0)^\top

\mathbf{x} = (3, 1, 0):

z = 1.5 + 0.5 = 2

\hat{\mathbf{x}} = (2, 2, 0)

Error: 1^2 + 1^2 + 0^2 = 2. One number cannot keep the difference between the first two features.

Linear autoencoders and PCA

With g(t) = t and squared error, the best code space is spanned by the first q principal components (Topic 18):

\min J = \sum_{k=q+1}^{d} \lambda_k
(7)

Same reconstructions as PCA. Example: eigenvalues 3 and 1, q = 1: best error 1.

Nonlinear activations let the decoder bend.

Figure 3:(b) A 2, 1, 2 linear autoencoder, trained in this page by gradient descent.

Part 2

What the code is good for

Maps of the data, cleaner inputs and unusual examples.

A map of the data

With q = 2, the code of every example is a point we can plot.

Examples that look alike get nearby codes: 0 near 6, 1 near 7. The groups come from the pictures alone.

Hinton and Salakhutdinov (2006) showed deep autoencoders giving clearer maps of digits than PCA.

Figure 5:Sketch of a 2-D code space for digit pictures. Colors are labels added only to read the plot.

Train on noisy copies

A denoising autoencoder gets a damaged input, for example with a random number added to every feature:

\tilde{\mathbf{x}}_i = \mathbf{x}_i + \text{noise}
(8)

The target stays the clean example:

J = \frac{1}{n} \sum_{i=1}^{n} \big\lVert \mathbf{x}_i - g_{\boldsymbol\psi}\big(f_{\boldsymbol\phi}(\tilde{\mathbf{x}}_i)\big) \big\rVert^2
(9)

Copying the input now gives a large error, since the noise is not in the target. The network must learn what clean examples look like and pull each input toward them. A wide code is then allowed.

Example

\mathbf{x} = (1, 0, 1)

\tilde{\mathbf{x}} = (0.8, 0.3, 1.1)

Noisy input error:

0.2^2 + 0.3^2 + 0.1^2 = 0.14

Output (0.9, 0.1, 1.0):

0.1^2 + 0.1^2 + 0^2 = 0.02

Spotting odd examples

s(\mathbf{x}) = \lVert \mathbf{x} - g_{\boldsymbol\psi}(f_{\boldsymbol\phi}(\mathbf{x})) \rVert^2, \qquad \text{flag } \mathbf{x} \text{ if } s(\mathbf{x}) > \tau
(10)

Train on normal data only. Odd points rebuild badly, so their score is high, as in Topic 15. Example: 0.12 > \tau = 0.05 is flagged.

Sparse and convolutional

A sparse autoencoder may have a large code, but a penalty in J keeps most code units near zero for each example.

A convolutional autoencoder uses the filters of Topic 25. Its encoder shrinks an image into small feature maps, and its decoder grows them back.

Both still minimize the reconstruction error.

Figure 8:(a) Filled units are active for one example. (b) Blocks are stacks of feature maps.

Part 3

Generating new data

Decode codes that no example produced.

Holes in the code space

The decoder turns any code into an output. Decode a new code and we may get a new example.

In a plain autoencoder, codes can sit in scattered groups with empty space between them. A code from a gap decodes to nonsense.

We want codes packed in a known region with no gaps, so that a random code decodes to something sensible.

Figure 9:Sketch. (b) Codes of a variational autoencoder fill a round region around 0.

The variational autoencoder

In a variational autoencoder (VAE), the encoder outputs two vectors: a mean \boldsymbol\mu and a spread \boldsymbol\sigma.

The code is drawn at random near \boldsymbol\mu, with spread \boldsymbol\sigma. Each example maps to a small cloud of codes.

The decoder must rebuild the example from any code in that cloud, so nearby codes give similar outputs.

Figure 10:Bottom: one code dimension, a bell curve centered at \mu_1 with width \sigma_1.

Sampling the code

Draw standard noise, then stretch it by \boldsymbol\sigma and shift it by \boldsymbol\mu, entry by entry:

\mathbf{z} = \boldsymbol\mu + \boldsymbol\sigma \odot \boldsymbol\epsilon, \qquad \boldsymbol\epsilon \sim \mathcal{N}(\mathbf{0}, \mathbf{I})
(11)

This is the reparameterization. The randomness sits in \boldsymbol\epsilon, which needs no training. The code is a simple sum of \boldsymbol\mu and \boldsymbol\sigma, so backpropagation passes through it to the encoder.

After training, new data comes from decoding fresh codes \mathbf{z} \sim \mathcal{N}(\mathbf{0}, \mathbf{I}): no encoder needed.

Example

\boldsymbol\mu = (1, -0.5), \boldsymbol\sigma = (0.5, 2)

Noise \boldsymbol\epsilon = (0.4, -1):

z_1 = 1 + 0.5 \cdot 0.4 = 1.2

z_2 = -0.5 + 2 \cdot (-1) = -2.5

The VAE loss

The cost adds two terms for each example: the reconstruction error and a penalty \text{KL}_i on its codes:

J = \frac{1}{n} \sum_{i=1}^{n} \Big( \lVert \mathbf{x}_i - \hat{\mathbf{x}}_i \rVert^2 + \text{KL}_i \Big)
(12)

The penalty compares the bell curve of the codes with the standard one (mean 0, spread 1), summed over the q code dimensions:

\text{KL}_i = \sum_{j=1}^{q} \tfrac{1}{2}\big(\mu_j^2 + \sigma_j^2 - 1 - \ln \sigma_j^2\big)
(13)

It is 0 only when \mu_j = 0 and \sigma_j = 1. It keeps all codes near a standard bell curve and fills the gaps, while the first term keeps examples apart.

Example

\mu = 1, \sigma = 0.5:

\tfrac12(1 + 0.25 - 1 - \ln 0.25)

= \tfrac12(0.25 + 1.386) \approx 0.82

\mu = 0, \sigma = 2: \approx 0.81. Too wide also costs.

\mu = 0, \sigma = 1: 0.

Two ways to generate

Both models turn a random code into a new example.

A VAE learns an encoder and a decoder, using reconstruction error plus the KL term.

A generative adversarial network (Topic 28) trains a generator against a judge network that tells real from generated examples; its samples are often sharper than a VAE's.

Strengths and weaknesses

Table 2:Autoencoders at a glance.

StrengthsWeaknesses
Learn from data without labelsNeed much data and training time
Follow curved structure that PCA missesCode axes are hard to interpret
One idea, many uses: maps, denoising, anomaliesCode size and network shape must be chosen
The encoder can feed later modelsA wide code may learn a plain copy
A VAE gives a smooth space to generate fromReconstructions and samples are often blurry
When to use it

Many unlabeled examples with structure that is not a straight line: images, signals, sensor readings.

Key ideas

Remember
  • An autoencoder learns to output its own input through a small code, with no labels.
  • It minimizes the reconstruction error; a linear one finds the PCA subspace.
  • Nonlinear layers let the code follow curved data.
  • The code gives maps of the data; noisy inputs teach denoising; large errors flag anomalies.
  • A VAE samples \mathbf{z} = \boldsymbol\mu + \boldsymbol\sigma \odot \boldsymbol\epsilon and adds a KL term, so random codes decode to new data.
