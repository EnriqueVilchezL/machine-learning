Part 1

Why hold data out

A score on data the model has already seen tells us very little.

Studying vs memorizing

A student who memorizes the answers of last year's exam gets full marks on that exam. On a new exam, the memorized answers do not help.

A model can do the same with its training data. Only questions it has never seen show whether it understood.

The idea

Keep some examples hidden during training and use them as the exam.

Figure 1:Scores of two models. The memorizer is perfect on its training data and much worse on new data.

Training and test error

The error of a model on a set is its average loss over the examples of that set:

\text{Err}_{\text{train}} = \frac{1}{n_{\text{train}}} \sum_{i \in \mathcal{D}_{\text{train}}} L\big(y_i, \hat{f}(\mathbf{x}_i)\big)
(1)
\text{Err}_{\text{test}} = \frac{1}{n_{\text{test}}} \sum_{i \in \mathcal{D}_{\text{test}}} L\big(y_i, \hat{f}(\mathbf{x}_i)\big)
(2)

For classes, the 0-1 loss counts 1 for a wrong answer and 0 for a right one. The error is then the share of mistakes:

L(y, \hat{y}) = \mathbb{I}(y \neq \hat{y}), \qquad \text{accuracy} = 1 - \text{Err}
(3)

Only \text{Err}_{\text{test}} uses examples the model never saw, so only it estimates the error on new cases.

Example

The memorizer of Figure 1 gets all training examples right:

\text{Err}_{\text{train}} = 0

On 20 new examples it gets 11 right:

\text{Err}_{\text{test}} = \tfrac{9}{20} = 0.45

\text{accuracy} = 1 - 0.45 = 0.55

The split in symbols

Shuffle the n examples, then cut them into two sets that share no example:

\mathcal{D} = \mathcal{D}_{\text{train}} \cup \mathcal{D}_{\text{test}}, \qquad \mathcal{D}_{\text{train}} \cap \mathcal{D}_{\text{test}} = \varnothing
(4)

With a test share p, the two sizes are:

n_{\text{test}} = p\,n, \qquad n_{\text{train}} = (1 - p)\,n
(5)

The empty intersection \varnothing means that no test example is used to fit \hat{f}.

Example

Figure 2 with n = 40 and p = 0.2:

n_{\text{test}} = 0.2 \times 40 = 8

n_{\text{train}} = 0.8 \times 40 = 32

Training, validation and test

Figure 3:Each set has one job. Models learn on training data, we choose among them with validation data, and the test set gives the final score.

Warning

If you look at the test score and then change the model, the test set has become a second validation set. Its score is now too optimistic.

Part 2

Splitting well

A test set should look like the data the model will meet, and be large enough to trust.

Random vs stratified

Stratified: fraud share10%

Stratified: each class is split on its own, so the test set keeps 10%.

Figure 4:Top: current test sets, fraud in orange. Bottom: fraud share in the last 12 test sets.

Class shares

The share of class c is the number of its examples n_c over the total:

\pi_c = \frac{n_c}{n}
(6)

A stratified split cuts each class on its own, so the test set keeps the same share:

n_{\text{test},\,c} \approx \pi_c \, n_{\text{test}}
(7)

A random split matches \pi_c only on average. With a rare class, one test set can be far from it.

Example

200 payments, 20 of them fraud:

\pi_{\text{fraud}} = \tfrac{20}{200} = 0.10

A stratified test set of 40 gets 0.10 \times 40 = 4 fraud and 36 normal payments.

How noisy is a test score

Say the model is right with probability a on new data. The accuracy measured on n_{\text{test}} examples moves around a by about one standard error:

\text{SE} = \sqrt{\frac{a\,(1 - a)}{n_{\text{test}}}}
(8)

About 95% of measured scores fall within two standard errors of a.

The size sits under a square root: four times more test examples only halves the noise.

Example

The model of Figure 5 has a = 0.8.

With n_{\text{test}} = 20:

\text{SE} = \sqrt{0.16/20} \approx 0.089

so scores range about 80% ± 18 points.

With n_{\text{test}} = 1000:

\text{SE} \approx 0.013

so about 80% ± 2.5 points.

Part 3

Hidden traps

Sometimes a random split lets the answer slip into training.

Data with a time order

Figure 6:Monthly sales over three years. (a) A shuffled split lets the model train on months that come after the test months. (b) A split by date trains on the past and tests on the future, as in real use.

Keep each patient together

Several rows often come from one person: scans, visits or purchases.

If a patient is in both sets, the model can recognize the patient instead of the disease, and the test score looks too good.

Figure 7:Six patients, four scans each. Purple outlines mark patients in both sets.

Leakage checklist

Duplicates across sets

The same row in training and test is a question the model has already seen. Remove duplicates before splitting.

Preprocessing on all data

A scaler or imputer fitted on all rows has seen the test set. Split first, then fit on training only.

Future information

A feature recorded after the moment of prediction gives away the answer. Use only what is known at that moment.

Figure 8:Three common leaks. Each one makes the test score higher than the score the model will get in real use.

Key ideas

Remember
  • A model is judged on examples it never saw during training.
  • Training data teaches, validation data chooses, test data reports once.
  • Stratify when a class is rare, so the test set keeps its share.
  • Small test sets give noisy scores.
  • Split by time or by group when the data has that structure.
  • Split first, then preprocess using the training data only.
