Abstract

Figures in a paper are usually exported by hand and drift from the code that made them. We run each notebook as part of the build, so every figure, table and number on these slides comes straight from its source cell.

Introduction

Why figures drift from the code that produced them.

The export step is where errors enter

Most figures pass through a manual copy before they reach a paper or a talk.

  • Plots are saved, renamed and pasted by hand
  • Numbers in the text are retyped from notebook output
  • Later changes to the data rarely reach the slides
Based on 48 interviews with lab groups, 2025. Compare with literate programming and executable papers.

Model

Each output is a deterministic function of its inputs and environment:

An output is reproducible if rebuilding with the same x and e returns the same bytes.
x: input data. e: pinned environment. θ: fitted parameters.

Builds are stable under caching

If every cell is keyed by the hash of its source and inputs, a cached build equals a clean build.

A cell is reused only when its key matches, so its output is the output of the same function on the same arguments. Induct over the cell order. ∎

A figure is a labelled cell

The label fig-error is what the slide references; the image is rebuilt on every run.

Keep one figure per cell so labels stay one-to-one.
